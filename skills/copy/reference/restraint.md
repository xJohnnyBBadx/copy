# Restraint: read before any rewrite

The default failure of an AI editor is confident, generic over-editing. This file is the floor every rewrite stands on, including a one-line example inside a critique.

## The leave-alone test

Before changing any passage, answer three questions:
1. **What is the named problem?** It must map to a rubric dimension or a confirmed pattern in [tells.md](tells.md).
2. **Is it a problem for this reader, in this context?** Check the profile's "Don't flag" list in [contexts.md](contexts.md).
3. **Is the change clearly better on that dimension, or only different?**

If any answer is no, leave it. "Different" is not an improvement.

## Preserve, always

Unless the author asks for a change, keep:
- **Meaning and claims,** including their strength and scope. A rewrite must not make a claim stronger, broader, or more certain than the source.
- **Facts, figures, names, dates, quotes, product names, prices, legal and regulatory text.** Flag problems with them; never fix them by guessing.
- **Brand vocabulary and signature phrases** from BRAND.md, even when they would trip a pattern list.
- **Deliberate devices:** anaphora, fragments, repetition, rhythm, wordplay, humour, unusual but working word choices.
- **The author's register and mechanics:** formality, person (we / you / I), sentence-length range, punctuation habits, regional spelling, capitalization style.

## Over-editing to avoid

These are the most common ways an editor makes good copy worse:
- Deleting every adverb, em dash, or passive construction because a rule list said so.
- Replacing a specific, unusual word with a common one.
- Evening out sentence lengths, or turning every paragraph's last line into a punchline.
- Adding benefit language, calls to action, or urgency to writing whose job isn't persuasion.
- Adding "you" framing to writing that works in the first person.
- Flattening humour, edge, or warmth into neutral corporate tone.
- Shortening by default. Shorter is better only when the cut material wasn't doing work.
- Simplifying vocabulary that the stated reader uses and expects.
- Introducing the stock phrases this skill flags ("unlock", "seamless", "it's not X, it's Y").

## Rewrite in the author's voice

- Use their vocabulary before yours. If they say "folks," don't write "people."
- Stay inside their sentence-length range and punctuation habits.
- Match their person and tense.
- If a BRAND.md exists, follow its rules and "this, not that" pairs. Do not reuse exemplar sentences word for word unless they are listed as signature phrases.

## Never add

- New facts, numbers, statistics, customer names, quotes, testimonials, awards, or results.
- New promises or guarantees.
- Research findings or audience insights the user didn't supply.

When a revision needs proof the source doesn't contain, write a placeholder: `[NEEDS: average setup time, with source]`. When weakening an overclaim, offer the honest version and, if useful, the version the author could use once they have proof.

## Edit budget

- `polish` changes as little as possible. If more than about a quarter of the sentences would need to change, stop: the piece needs `critique`, not polish. Say so and offer to critique.
- Examples inside `critique` rewrite the passage at the level of the problem: a strategic problem gets a new angle or headline, not a tidier sentence.
- Never return a full rewrite unless one was asked for.

## Self-check after every rewrite

Compare each changed passage with the original:
- Does it still read as the same author?
- Did any claim get stronger, broader, or more certain?
- Did any fact, number, or name appear that wasn't in the input?
- Did a deliberate device disappear?
- Is it better on the named dimension, rather than just different?
- Would a sharp editor reading only this change agree that it fixes the named problem?

Revert any change that fails a check.
